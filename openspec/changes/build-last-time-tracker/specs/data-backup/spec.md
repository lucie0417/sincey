# Spec Delta

## Purpose

讓使用者能將自己的全部事件匯出保存，並在原瀏覽器或新的匿名資料空間還原。以完整驗證、筆數預覽及確認後取代的方式，明確處理既有資料，避免不完整匯入造成生活紀錄遺失或跨使用者資料混淆。

## ADDED Requirements

### Requirement: 匯出完整備份
系統 SHALL 提供可下載的版本化 JSON 備份，包含目前使用者全部事件的標題、最近日期與完整備註，不包含匿名憑證或內部使用者識別資料。

#### Scenario: 匯出含空日期的資料
- **WHEN** 使用者匯出包含同名事件與空日期的資料
- **THEN** 下載可還原全部事件內容的 JSON 檔，其他人的資料不在檔案中

### Requirement: 匯入驗證與預覽
系統 SHALL 在取代前驗證檔案版本、結構、全部欄位與日期，顯示目前與備份筆數並要求明確確認；不合規、未知版本或含未來日期的備份 SHALL 被拒絕。

#### Scenario: 確認與取消
- **WHEN** 使用者選擇有效備份並看到目前 3 筆、備份 5 筆的預覽後取消
- **THEN** 目前 3 筆事件完全不變

#### Scenario: 無效檔案
- **WHEN** 備份包含錯誤格式、未知版本或無效日期
- **THEN** 顯示可理解的錯誤且不改動任何既有資料

### Requirement: 原子取代
系統 MUST 在確認後原子性地完整取代目前匿名資料空間的事件，不合併、不依標題去重，也不影響其他使用者；任何寫入失敗都 SHALL 保留原資料。

#### Scenario: 新瀏覽器還原
- **WHEN** 新瀏覽器的使用者確認匯入有效備份
- **THEN** 備份內容出現在目前資料空間，原瀏覽器資料與憑證不會被連結或改動

#### Scenario: 空備份與交易失敗
- **WHEN** 使用者確認匯入零筆的有效備份
- **THEN** 成功時清空自己的事件，若交易失敗則保留全部原資料
