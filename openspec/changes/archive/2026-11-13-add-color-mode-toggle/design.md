# Design

## Context

動機與功能範圍見 proposal.md，行為契約見 `specs/color-mode/spec.md`。目前 `client/App.tsx` 的 App 位於 Routes 外，頁首也位於資料載入與錯誤分支之外，適合持有不隨換頁重建的模式狀態。`client/style.css` 已載入 Tailwind CSS v4，但配色多為各選擇器的固定色碼；`client/index.html` 的 theme-color 固定為米白。沒有現有主題儲存、系統配色監聽或相關測試。

既有 `event-records` 要求溫暖、柔和中性色；深色採同一風格即可相容，不需修改事件需求。專案已有 Playwright 手機尺寸設定與實際 API／PostgreSQL 測試。本變更跨共用頁首、根元素、全站樣式與測試，因此保留此設計文件。

## Goals / Non-Goals

**Goals:**
- 以現有 React 狀態與 CSS 自訂屬性完成共用配色，避免複製兩套元件或大量逐元件條件判斷。
- 明確控制新文件的淺色初始值，以及同一應用內導航的連續性。
- 納入頁首、表單、訊息及原生控制項的配色提示，確保切換覆蓋完整。

**Non-Goals:**
- 不引入主題套件、圖示套件、狀態管理工具或調整依賴版本。
- 不重構無關事件邏輯、修改 API、schema、migrations、匿名 cookie 或備份格式。
- 不增加系統模式、儲存偏好、跨分頁同步、自訂色盤或切換動畫。

## Decisions

### 模式狀態與作用範圍

由 App 持有 `light | dark` 狀態，初始值固定為 light，切換只更新此狀態；不要以主題作為 Routes 或表單的 key，以免重建元件造成輸入遺失。模式同步至 `document.documentElement` 的 `data-color-mode`，使根背景、body 與 shell 外的 undo、toast 同樣生效；卸載時清理屬性及相關副作用，避免開發模式殘留。

不讀寫 localStorage、sessionStorage、cookie 或後端，不讀取或監聽系統主題。相較把狀態放在每個頁面，App 層不會因 React Router 換頁重設；相較導入全域主題 provider，目前只有頁首控制，不需要額外 abstraction 或依賴。

### 顏色變數與原生控制項

在 style.css 的預設根規則定義淺色語意變數，在 `[data-color-mode='dark']` 覆寫深色值，保留 Tailwind 匯入與既有版面規則。依角色整理頁面背景、表面、輸入背景、主要／次要／弱化文字、邊框、主按鈕、hover、disabled、focus、錯誤、危險操作、通知與陰影；不同角色即使目前同色，也可使用不同變數，避免深色互動狀態被錯誤合併。

淺色盡量沿用現有色值；深色以暖深灰表面、柔和米白文字與灰綠點綴，具體色值在實作時以手機及桌面截圖檢視決定。替代方案為替每個既有選擇器追加 dark 覆寫，會讓大量固定色碼與狀態規則難以保持一致，因此選擇集中變數。

根元素依模式明確設定 `color-scheme: light` 或 `dark`，不使用 `light dark` 的自動選擇，讓日期、檔案輸入等原生控制項採對應提示。可同步更新既有 `meta[name='theme-color']` 為當前背景色；瀏覽器是否套用工具列顏色屬平台行為，不作跨平台逐像素驗收。首次樣式預設必為淺色，不需要啟動時讀儲存或插入偏好偵測腳本。系統檔案選擇器等網站外 UI 不納入自訂主題範圍。

### 切換入口與頁首

頁首右側將切換按鈕與既有備份連結放入共同操作區，使用原生 `type='button'`，可見文字與可存取名稱一致，分別為「切換為深色」與「切換為淺色」。不僅以圖示或顏色表示動作。保留明確焦點樣式；手機寬度不足時調整間距或換行，不隱藏備份入口，不擴大頁面寬度。

共用頁首不依賴 API ready 狀態，因此載入及錯誤畫面也能切換。切換不呼叫 reload、initialize 或任何記事／備份 API，不調整 undo 的 expires、表單或搜尋狀態。

### 驗證方式

新增 `tests/color-mode.spec.ts`，沿用現有 Playwright；使用系統淺色及深色模擬驗證兩者都以淺色開始，切換系統設定不改網站模式。測試雙向切換、各路由內導航、直接載入、重新整理、新分頁與鍵盤操作，並以 computed style／可見結果確認配色確實變化，不只檢查屬性。

用受控 API 攔截觸發載入、失敗、復原及通知；使用真實 API 的既有測試驗證功能未退化。監測切換前後的資料請求與表單／搜尋／復原期限，驗證切換沒有副作用。檢查未新增主題持久儲存，不把既有匿名 cookie 誤當成主題偏好。

手機與桌面分別檢視首頁、表單、備份與訊息狀態的兩色截圖；日期原生選擇器的外觀僅驗證配色提示與可操作性，不要求不同作業系統完全相同。README 增補「換頁維持、重新整理回淺色」說明。

## Risks / Trade-offs

- [固定色碼多，容易遺漏錯誤或停用狀態] → 依元件與狀態盤點，完成後搜尋剩餘色碼並檢視兩色畫面。
- [手機頁首增加文字後擁擠] → 以目前手機測試設定檢查可見性、觸控操作與無橫向溢出。
- [只替換 shell 背景會遺漏根元素與提示] → 主題屬性放在 html，涵蓋所有現有渲染區域。
- [重新整理回淺色可能與常見網站習慣不同] → 這是使用者確認的行為，明確記錄並測試，不自行加入偏好保存。

## Migration Plan

本變更僅前端資源與測試／文件，無資料遷移或環境變數調整。完成後執行型別、lint、格式、建置、主題測試及現有測試；部署沿用原方式。若需回退，回復此次前端、測試及文件變更並重新建置，不影響既有伺服器資料。
